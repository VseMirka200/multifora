# SignPath Foundation: безопасная подготовка «Мультифоры»

SignPath Foundation — потенциальный бесплатный способ подписывать Windows
приложения для одобренных open-source проектов. Заявка **отправлена**;
одобрение и параметры SignPath ещё не получены. До ответа сервиса нельзя
утверждать, что цифровая подпись настроена или доступна.

Эта стадия **не является подключением SignPath API и не подписывает EXE**.
Она готовит и проверяет формат исходных файлов, которые можно использовать
для согласования конфигурации проекта в SignPath. Никаких API-токенов,
ключей или выдуманных URL сервиса в репозитории нет.

## Что готово в GitHub Actions

В `.github/workflows/windows-build.yml` после сборки и проверки
установщика выполняется:

```powershell
python scripts/prepare_signpath_payloads.py --app dist/Multifora/Multifora.exe --installer dist/installer/Multifora-Setup-1.0.4.exe --output dist/signpath-staging
```

Версия `1.0.4` здесь — **пример**, а workflow автоматически использует
имя реально созданного установщика.

Результаты включаются в обычный Actions-артефакт `Multifora-Windows-build`
после `workflow_dispatch` или при проверке PR:

| Имя | Содержимое | Назначение |
| --- | --- | --- |
| `signpath-staging/Multifora-app-unsigned.zip` | Только `Multifora.exe` в корне ZIP | Ознакомление и настройка SignPath |
| `signpath-staging/Multifora-installer-unsigned.zip` | Только `Multifora-Setup-<version>.exe` в корне ZIP | Ознакомление и настройка SignPath |
| `signpath-staging/manifest.json` | Размеры и исходные SHA-256 обоих EXE, `signed: false` | Проверка того, что отправляется на подпись |

Скрипт отклоняет пустые, чрезмерно большие и неправильно названные
файлы, проверяет содержимое ZIP и не перезаписывает существующую папку
выхода. Архивы **не должны** публиковаться как подписанные релизы.

## Что делать после ответа SignPath

1. Уточнить, одобрена ли именно заявка Foundation, какую GitHub
   интеграцию и конфигурацию подписываемых артефактов предоставляет сервис.
2. Получить точные названия идентификаторов организации, проекта,
   signing policy и artifact configuration **из SignPath** (не угадывать).
3. Подготовить отдельный PR для фактического вызова поддерживаемого
   SignPath API или официального GitHub Action; зафиксировать проверенную
   версию Action и минимально необходимые права.
4. Настроить секреты и одобрение подписи через защищённый GitHub
   Environment. Не выдавать доступ к токену SignPath PR из форков
   или неподтверждённым коммитам.
5. Подписывать `Multifora.exe` **перед** упаковкой Inno Setup,
   затем подписывать **готовый установщик** и только после этого
   вычислять SHA-256 и ZIP для релиза.
6. Сверять `Get-AuthenticodeSignature` и ожидаемую публичную
   идентичность подписанта **перед публикацией**. Настоящий SHA-256
   сертификата можно закрепить только после получения достоверного
   публичного сертификата и проверки легитимного подписанного файла.
7. Отдельно усилить **клиентский автообновлятор**: только после
   настройки и проверки доверенной подписи блокировать запуск
   установщика с чужой или недействительной подписью.

Подписанные файлы, полученные из `windows-build.yml` после ручной
операции, не являются готовым официальным релизом: подписанный
`Multifora.exe` должен попасть внутрь **нового** подписанного
установщика. Нельзя просто опубликовать ранее собранный установщик
из тестовой сборки.

## Почему release.yml пока не вызывает SignPath

API, правила подписи и способ аутентификации определит организация
SignPath после одобрения. Пока интеграция не проверена, выдуманный
API-вызов мог бы сломать выпуск либо обойти проверку.

Если для репозитория установить GitHub Actions Variable
`MULTIFORA_SIGN_PROVIDER=signpath`, нынешний release workflow
**намеренно завершится ошибкой до сборки и публикации**. Не включайте
этот режим до отдельного PR с проверенной реализацией SignPath.

По умолчанию `MULTIFORA_SIGN_PROVIDER` не задан, поэтому процесс
выпуска остаётся прежним; старый опциональный PFX-вариант по
`MULTIFORA_SIGN_RELEASE=true` не изменён. Тег `v1.0.3` и
опубликованные файлы менять нельзя.

**Не пересылайте в чат токены SignPath, ключи, пароли или PFX.**

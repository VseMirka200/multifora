Участие в разработке

Спасибо за желание помочь Мультифоре. Принимаются исправления ошибок, тесты, улучшения интерфейса и документации, а также согласованные новые функции.

Перед началом

  • Уязвимости отправляйте по инструкции из раздела безопасности, а не публично.
  • Соблюдайте Кодекс поведения.

Среда разработки

Проект рассчитан на Windows и Python 3.11+.

```powershell

git clone https://github.com/VseMirka200/multifora.git

cd multifora

py -3 -m venv .venv

.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt

.\.venv\Scripts\python.exe multifora_start.py

```

Microsoft Word требуется только для части операций с документами, Ghostscript — для сжатия PDF.

Внесение изменений

  1. Создайте ветку от актуальной main.
  2. Ограничьте Pull Request одной понятной задачей.
  3. Сохраняйте существующую структуру app, core/workers и tests.
  4. Добавляйте тест для исправленной ошибки или нового поведения.
  5. Не добавляйте виртуальные окружения, сборки, кэши, локальные настройки и пользовательские файлы.

Проверки

```powershell

$env:QT_QPA_PLATFORM = "offscreen"

.\.venv\Scripts\python.exe -m pytest -q

.\.venv\Scripts\python.exe -m ruff check .

```

Если Ruff не установлен:

```powershell

.\.venv\Scripts\python.exe -m pip install ruff

```

Pull Request

В описании укажите:

  • какую проблему решает изменение;
  • что именно изменено;
  • как это проверено;
  • известные ограничения;
  • снимки экрана для заметных изменений интерфейса.

Изменения в main следует вносить через Pull Request. Все обязательные проверки CI должны завершиться успешно. Если у проекта появится второй сопровождающий, рекомендуется требовать одобрение независимого ревьюера. Автор не может одобрить собственный PR. Сопровождающий может запросить более узкий объём, дополнительные тесты или изменение реализации.

Не добавляйте токены, ключи и приватные файлы ни в коммиты, ни в Pull Request. Проверяйте изменения GitHub Actions и сторонних исполняемых файлов особенно тщательно.

Стиль коммитов

Используйте короткие сообщения в повелительной форме, описывающие результат, например Исправить добавление нескольких файлов. Не смешивайте рефакторинг и изменение поведения без необходимости.

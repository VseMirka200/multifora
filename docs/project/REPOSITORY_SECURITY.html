Защита репозитория Мультифора

Этот документ — чек-лист для владельца репозитория. Файлы в Git не включают настройки доступа GitHub автоматически: пункты в интерфейсе GitHub нужно проверить и включить отдельно.

Ветка main

Откройте Settings → Rules → Rulesets (или Settings → Branches, если используются старые правила защиты). Для main:

  1. Требуйте прохождения изменений через Pull Request. Не разрешайте принудительную перезапись ( force push ) и удаление ветки.
  2. Требуйте актуальную ветку перед слиянием и успешные проверки: test-windows, windows-build, dependency-audit, CodeQL (Python). Если проверка переименована, обновите правило после её первого успешного запуска. После проверки нового workflow можно добавить dependency-review.
  3. Включите применение защиты к администраторам, если такой вариант доступен. Не выдавайте обход правил Actions-ботам и интеграциям без конкретной причины.
  4. Для единственного разработчика не включайте обязательное одобрение другого человека: автор не может одобрить свой PR, и это заблокирует работу. Когда появится независимый сопровождающий — требуйте минимум одно одобрение и сбрасывайте старые одобрения при изменении PR.
  5. Не требуйте подписанные коммиты, пока не настроена подпись всех легитимных путей внесения изменений (включая GitHub UI и ботов). Для новых веток используйте PR, а не прямые коммиты в main.

Безопасность и оповещения

Проверьте Settings → Advanced Security или Security and quality (названия могут отличаться):

  • Включите Dependabot alerts и Dependabot security updates при их доступности. Плановые PR обновления версий отдельно отключены намеренно; не путайте их с экстренными исправлениями уязвимостей.
  • Включите Secret scanning и Push protection (если доступны). При обнаружении настоящего секрета отзовите и перевыпустите его, а не ограничивайтесь удалением строки из новой версии.
  • Убедитесь, что Private vulnerability reporting доступен по ссылке в разделе безопасности; периодически просматривайте CodeQL, Dependabot и результаты pip-audit.
  • Для Actions задайте default GITHUB_TOKEN permissions: read-only и запретите Actions автоматически создавать/одобрять PR, если это не требуется. В релизном процессе право contents: write выдаётся только отдельной задаче публикации.
  • Проверяйте изменения workflow вручную. Для сторонних actions по возможности используйте проверенные неизменяемые SHA коммитов вместо плавающих ссылок на ветки или теги.

Публикация релизов

  1. Выпускайте релизы только из проверенного кода main. Перед созданием тега убедитесь, что все обязательные проверки прошли, а версия соответствует app/core/app_identity.py.
  2. Защитите теги по шаблону v* через Rulesets, запретите нежелательное удаление/перезапись тегов и ограничьте их создание доверенными сопровождающими, если это поддерживается тарифом и настройками.
  3. Проверяйте результаты Windows-сборки и smoke-тестов перед распространением. Workflow публикует ZIP и установщик вместе с SHA-256; эти суммы служат для проверки целостности, не являются цифровой подписью издателя.
  4. Бинарные файлы bin/gswin64/ входят в репозиторий: перед заменой проверяйте официальный источник, версию, лицензию, SHA-256 и наличие исправлений известных уязвимостей. Не принимайте бинарники из непроверенных PR.
  5. Рассмотрите подписывание Windows-установщика сертификатом издателя и аттестации сборок (artifact attestations) перед публичным распространением приложения.

При инциденте

  • Утечка ключа: немедленно отзовите его, изучите действия с момента утечки и только затем очистите код и историю.
  • Уязвимая библиотека: проверьте затронутые релизы, обновите зависимость, повторите тесты и опубликуйте исправление.
  • Уязвимость продукта: используйте приватный GitHub Advisory, не раскрывайте эксплойт в публичном Issue до согласованного исправления.
  • Подозрительная сборка: приостановите распространение, проверьте исходники, зависимости и логи CI, затем перевыпустите артефакты.

Ограничение: защита main, сканирование секретов, частные уведомления и правила тегов требуют настроек GitHub, этот документ сам по себе их не включает.

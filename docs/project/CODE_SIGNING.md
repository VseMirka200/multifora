# Подпись Windows-релизов (Authenticode)

Релизные Git-теги защищены GitHub Rulesets. Перед выпуском также проверяется,
что коммит тега входит в историю защищённой ветки main.

## Что умеет процесс сборки

После включения подписания Windows workflow для тегов v*:

1. Собирает и проверяет dist/Multifora/Multifora.exe.
2. Подписывает Multifora.exe сертификатом издателя, заверяет время подписи
   службой RFC 3161 и проверяет статус Authenticode и SHA-256 DER сертификата.
3. Упаковывает уже подписанный EXE в установщик Inno Setup.
4. Подписывает установщик Multifora-Setup-<version>.exe и повторяет проверку.
5. Только затем упаковывает ZIP, вычисляет SHA-256 и публикует GitHub Release.

При ошибке подписи или проверки сборка падает до публикации релиза.
Контрольные суммы создаются **после** подписи; иначе подпись изменила бы файл
и прежние контрольные суммы перестали бы совпадать.

## Подготовка сертификата

Нужен действующий, доверенный Windows сертификат **Code Signing** от
доверенного удостоверяющего центра, с доступом к закрытому ключу на
одноразовом Windows runner. Этот вариант интеграции поддерживает
импортируемый файл PKCS#12 (.pfx) с паролем. Если ключ хранится в
HSM, USB-токене или облачной службе подписи и экспортировать его нельзя,
понадобится **отдельная интеграция с этим провайдером**, а не PFX.

**Не добавляйте .pfx, пароль, закрытый ключ или их Base64 в Git,
Pull Request, CI-журналы или переписку.** Не используйте самоподписанный
сертификат для настоящих релизов: он не пройдёт проверку доверия Windows.

Из публичного сертификата издателя (.cer) вычислите SHA-256
**DER-байтов сертификата**. Это не SHA-256 установщика, не отпечаток PFX
и не стандартный SHA-1 thumbprint из интерфейса Windows:

~~~powershell
$cert = [System.Security.Cryptography.X509Certificates.X509Certificate2]::new('publisher.cer')
$sha256 = [System.Security.Cryptography.SHA256]::Create()
try {
    [BitConverter]::ToString($sha256.ComputeHash($cert.RawData)).Replace('-', '')
} finally {
    $sha256.Dispose()
    $cert.Dispose()
}
~~~

В GitHub в **Settings → Secrets and variables → Actions** создайте:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | MULTIFORA_CODESIGN_PFX_BASE64 | Base64 **всего бинарного** файла .pfx |
| Secret | MULTIFORA_CODESIGN_PFX_PASSWORD | Пароль файла .pfx |
| Variable | MULTIFORA_SIGNER_CERT_SHA256 | 64 символа: SHA-256 DER сертификата |
| Variable | MULTIFORA_SIGN_RELEASE | true |

Base64 можно получить локально, не печатая содержимое в терминале,
и вставить через защищённый интерфейс GitHub. Не отправляйте его в чат.
Разрешите доступ к секретам только доверенному workflow; регулярно
проверяйте права записи в репозитории и доступ к Secrets.

**Включайте MULTIFORA_SIGN_RELEASE=true только после настройки остальных
значений.** Если переменная отсутствует или равна false, обычная сборка
продолжится **без цифровой подписи** и выведет предупреждение. Если она
равна true, но сертификат, пароль, отпечаток или проверка отсутствуют,
сборка завершится ошибкой, **не публикуя** релиз.

## Проверка и ограничения

- CI для Pull Request не получает секреты подписи и по-прежнему
  проверяет сборку на неподписанных тестовых артефактах.
- Автоматическая публикация использует те же защищённые теги v*;
  не создавайте пробный тег v*, если не намерены запустить настоящий релиз.
- Подписываются приложение Multifora.exe и установщик Inno Setup.
  Скрипт тихой установки .bat и сторонние бинарные файлы отдельно
  не подписываются данным шагом.
- Уже опубликованный v1.0.3 **не переподписывается** и не изменяется.
- **Верификация издателя на стороне автообновления — отдельный этап.**
  Текущий updater проверяет URL, размер, версию и SHA-256, но ещё
  не содержит закреплённого SHA-256 сертификата издателя. После получения
  реального сертификата его публичный отпечаток нужно зафиксировать
  в коде обновления и добавить обязательную проверку доверенной подписи
  перед запуском установщика.

Для закрытых ключей в аппаратных и облачных хранилищах предпочтителен
выделенный сервис подписания с ограниченными правами и подтверждением
выпуска. Не пытайтесь экспортировать неэкспортируемые ключи.

# Архитектура Мультифоры

Этот документ помогает участникам быстро определить место изменения и не смешивать интерфейс, состояние приложения и файловые операции.

## Основные части

| Путь | Назначение |
| --- | --- |
| `multifora_start.py` | точка входа, создание Qt-приложения, выбор первого экземпляра |
| `app/ui/ui_main.py` | главное окно, сборка интерфейса, IPC-сервер |
| `app/ui/mixins` | действия интерфейса, настройки, шаблоны и интеграция с Windows |
| `app/ui/ui_components.py` | переиспользуемые Qt-компоненты |
| `app/ui/ui_styles.py`, `theme_styles.py` | стили и темы |
| `app/core` | настройки, форматы, IPC, обновления и вспомогательная логика |
| `core/workers` | фоновые операции над файлами |
| `tests` | модульные, интеграционные и UI smoke-тесты |
| `scripts` | локальная сборка приложения и установщика |
| `.github/workflows` | CI и публикация релизов |

## Поток выполнения

1. `multifora_start.py` создаёт `QApplication` и собирает пути из аргументов.
2. Windows mutex определяет первый экземпляр.
3. Дополнительные экземпляры передают файлы через локальный IPC либо дисковую очередь.
4. Главное окно добавляет пути в модель списка.
5. UI формирует параметры операции и запускает подходящий worker.
6. Worker выполняет файловую работу вне основного UI-потока и сообщает прогресс сигналами Qt.

## Правила зависимостей

- UI может использовать `app/core` и `core/workers`.
- Worker не должен зависеть от виджетов главного окна.
- Повторяемая бизнес-логика должна находиться вне обработчиков сигналов UI.
- Реестр поддерживаемых форматов хранится централизованно в `app/core/conversion_formats.py`.
- Настройки должны читаться и записываться через `app/core/settings.py`.
- Ошибки фоновых задач возвращаются структурированным результатом, а не показывают окна напрямую.

## Потоки и отмена

Файловые операции выполняются в фоновых workers. Виджеты изменяются только из главного Qt-потока. Отмена является кооперативной: worker проверяет запрос между безопасными этапами; внешние процессы могут завершить текущий шаг не мгновенно.

## Интеграция с Windows

Регистрация контекстного меню и ярлыков находится в `windows_integration_mixin.py`. Передача файлов между экземплярами реализована в `app/core/app_ipc.py`. Изменения этой части должны проверять сценарии с закрытым и уже открытым приложением, путями с пробелами и множественным выделением.

## Тестирование изменений

- чистая логика: отдельные unit-тесты;
- UI-поведение: тесты с `QT_QPA_PLATFORM=offscreen`;
- исправление ошибки: регрессионный тест;
- интеграция Windows: тестируемая генерация команд и ручная проверка на поддерживаемой Windows.

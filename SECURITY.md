# Политика безопасности

Исправления безопасности выпускаются для последней опубликованной версии Мультифоры. Старые версии могут не получать обновления.

## Сообщить об уязвимости

Не публикуйте детали уязвимости в открытом issue, Pull Request или обсуждении. Используйте [приватный GitHub Security Advisory](https://github.com/VseMirka200/multifora/security/advisories/new).

Укажите затронутую версию, последствия, минимальные шаги воспроизведения и возможное исправление. Удалите из логов и вложений личные пути, документы, токены и другие конфиденциальные данные.

Если форма Advisory недоступна, используйте контакт, опубликованный в [профиле сопровождающего](https://github.com/VseMirka200). Если связаться конфиденциально не удалось, создайте issue только с просьбой предоставить закрытый канал; не включайте описание уязвимости, пример эксплуатации или вложения. GitHub-профиль сам по себе не является формой личных сообщений.

Согласуйте с сопровождающим исправление и срок публикации подробностей. До согласования не раскрывайте технические детали в открытых обсуждениях.

Политика охватывает исходный код, официальный установщик, portable-сборку и процесс обновления.

## Проверка выпусков

Скачивайте приложение со [страницы релизов проекта](https://github.com/VseMirka200/multifora/releases/latest). Сравнивайте SHA-256 с файлом `.sha256` того же выпуска. Контрольная сумма проверяет целостность скачанного файла и не является цифровой подписью издателя.

Настройки защиты ветки, приватных сообщений об уязвимостях и оповещений задаются в GitHub отдельно. Наличие этой политики не подтверждает, что все эти настройки включены.
